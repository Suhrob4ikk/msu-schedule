# МГУ Душанбе — Расписание занятий

Приложение с расписанием занятий филиала МГУ им. Ломоносова в Душанбе. Данные берутся
с официального сайта **msu.tj**. Три части: backend (API), web (сайт), mobile (Android).

Язык общения с пользователем — **русский**. Пользователь — владелец проекта (не всегда
технический): объясняй простыми словами, делай сам, не проси подтверждений на мелочи.
На деплой в прод и на необратимые действия — спрашивай.

Аудитория — примерно 20–30 студентов. Нагрузка мизерная, оптимизировать под масштаб не нужно;
цена ошибки — не в производительности, а в неверных данных на экране.

## Как течёт информация

```
msu.tj (enf.xls, gf.xls)  →  backend качает и парсит  →  SQLite  →  REST API /api/*
                                                                      ↓
                                                       web (Vercel) и mobile (APK)
                                                       только рисуют ответ API
```

- Синхронизация каждые 2 часа (`services/scheduler.py`) + при старте приложения.
- HTML-страницы расписания на msu.tj закрыты анти-ботом (HTTP 416) — скрапить нельзя.
  Файлы XLS не закрыты, их и качаем. Мёртвый код скрапера остался в `parser.py`
  за флагом `SCRAPE_HTML_TEACHERS = False` — на случай, если защиту снимут.

### ⚠️ База эфемерная

На бесплатном тарифе Render **нет диска**. SQLite-файл живёт в файловой системе контейнера
и **стирается при каждом деплое**. Это не авария:

- расписание восстанавливается само первой синхронизацией при старте;
- **теряются** регистрации пользователей (`user_registrations`), подписки на web-push
  (`user_subscriptions`) и история изменений (`schedule_changes`).

Если это станет важно — нужен платный тариф с диском или внешняя БД. Ранее в этом файле
было написано, что база на volume и переживает деплой — **это было неверно**.

## Backend — ключевые файлы (`backend/app/`)

- `main.py` — запуск, lifespan (создание таблиц, индексы, миграция колонки `week_start`,
  `seed_rooms()` — чистка и дедуп аудиторий, `load_teacher_overrides()`, первая синхронизация), CORS.
- `core/config.py` — настройки из переменных окружения.
- `models.py` — таблицы: Faculty, Group, Teacher, Room, WeekSchedule, Lesson, ScheduleChange,
  UserSubscription, LessonNote, AttendanceRecord, UserRegistration, SyncLog,
  ExamNotificationLog, **TeacherOverride** (ручные замены ФИО).
- `services/parser.py` — разбор XLS (`parse_xls_file`, `parse_subject_cell`, `parse_room`),
  карта замен ФИО.
- `services/sync.py` — скачать → распарсить → сохранить → найти изменения → сбросить кэш → push.
- `services/scheduler.py` — периодическая синхронизация + ежедневные напоминания о зачётах в 07:00.
- `services/push.py` — web-push (VAPID). `send_push` возвращает `bool`.
- `api/routes/schedule.py` — основные эндпоинты, `enrich_lesson`, кэш свободных аудиторий.
- `api/routes/user.py` — регистрация, подписки, web-push.
- `api/routes/admin.py` — ручная синхронизация по заголовку `X-Admin-Secret`. **Все** маршруты закрыты ключом.
- `api/routes/dev.py` — скрытая панель разработчика (см. ниже).
- `api/routes/app_update.py` — `/api/app/version`: отдаёт последнюю версию мобильного из GitHub Releases.
- `api/routes/export.py` — экспорт в `.ics`.

### Переменные окружения (задаются на **Render → Environment**)

| Переменная | Зачем |
|---|---|
| `DATABASE_URL`, `DATA_DIR` | пути SQLite (`/opt/render/project/src/data`) |
| `ADMIN_SECRET` | заголовок `X-Admin-Secret` для `/api/admin/*` |
| `DEV_PANEL_PASSWORD` | пароль панели `/dev`. Пусто → панель полностью выключена (404) |
| `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` | web-push. **Потеря = все подписки мертвы** |

Копия значений — в `backend/.env.production` (в `.gitignore`, в репозиторий не попадает).
`backend/.env` — отдельный файл для локального запуска, продовые значения туда не класть.

### ⚠️ Главная ловушка веба (hydration #418)

Все страницы `"use client"`, но Next.js всё равно делает SSR. Читать `localStorage`
или `new Date()` прямо в инициализаторе `useState` **нельзя** — первый клиентский рендер
разойдётся с серверным. Инициализируй нейтральным значением, реальное ставь в `useEffect`.

Побочный эффект: `npm run lint` даёт ~15 ошибок `react-hooks/set-state-in-effect` —
это цена принятого паттерна, не баги. Сборку они не ломают.

Проверка перед пушем: `cd frontend && npx next build` — должно быть 0 ошибок.

## Что важно знать про данные

- 2 факультета (ЕНФ, ГФ), 6 направлений (ПМиИ, ХФММ, Геология, ГМУ, МО, Лингвистика),
  курсы 1–4 → **24 группы**. Пары хранятся понедельно, архив чистится через 14 дней.
- Полная неделя — примерно **600 пар**. Проверено симуляцией: сохраняются за ~2 сек,
  запросы 8–20 мс. Запас огромный.
- **Каникулы и сессия — не баг.** В июле-августе файл на msu.tj почти пустой,
  приложение показывает экран «Каникулы!».
- **Коды кафедр вместо ФИО:** в Excel иногда стоит «ИТУ» или «английский» вместо фамилии.
  Парсер берёт скобку с инициалами (`Предмет (код) (Фамилия И.О.)`), остальное правится
  через панель `/dev` → «Замены ФИО», применяется сразу без пересборки.
- **Совмещённые преподаватели.** В ячейке бывает «Стаценко Ю.Ю., Охонвалиева Ш.С.».
  Пара умеет ссылаться только на ОДНОГО преподавателя (`Lesson.teacher_id`), поэтому такая
  запись показывается в списке целиком, как есть. Разбивать её на две строки **нельзя** —
  так уже делали, и обе строки вели на один и тот же id, то есть на чужое расписание.
  Правильное решение (если понадобится) — связь многие-ко-многим и миграция.
- Аудитории в нижнем регистре (чтобы «лабФИЗ» и «лабфиз» были одной).
- `/free-rooms` отдаёт **все** группы в занятой аудитории (`occupied_list`) и флаг `conflict`,
  если их больше одной — это ловит накладки в расписании университета.

## Скрытая панель разработчика `/dev`

`https://frontend-ten-nu-80.vercel.app/dev` или кнопка «Режим разработчика» внизу профиля.
Пароль — `DEV_PANEL_PASSWORD`. Если переменная не задана, панель отдаёт 404 целиком.

Безопасность: пароль только из env, сравнение timing-safe, HMAC-токен на 24 ч в sessionStorage,
любая ошибка авторизации → **404** (панель нельзя обнаружить перебором), блок на 15 мин после 5 попыток.

| Раздел | Когда нужен |
|---|---|
| Счётчики и последняя синхронизация | первое, куда смотреть при «данные не те» |
| Группы без пар | главный индикатор в сентябре: группа в списке = парсер её не разобрал |
| Синхронизировать сейчас | не ждать 2 часа после обновления файла на msu.tj |
| Очистить кэш / Пересобрать аудитории | если аудитории показывают старое или появились дубли |
| **Замены ФИО** | главный рабочий инструмент: код кафедры → настоящая фамилия |
| Сырые данные по группе | увидеть ровно то, что получает приложение, и сверить с msu.tj |
| Тестовый push | проверить, что уведомления доходят |

## Сроки и то, что может протухнуть

| Что | Когда | Что сломается |
|---|---|---|
| **`GITHUB_API_TOKEN` на Render** | зависит от срока при выпуске | перестанет работать баннер «доступно обновление» |
| Токен `gh` на компьютере владельца | 26 окт 2026 | нельзя публиковать релизы, пока не обновить |
| `android/app/debug.keystore` | 2052 | не истечёт, **но лежит только на компьютере владельца** |

⚠️ **`debug.keystore` не в репозитории** (`android/` в `.gitignore`). Если файл потерять,
обновление не встанет поверх установленного приложения — у всех Android откажется ставить
APK с другой подписью, придётся удалять приложение и терять данные. Файл нужно бэкапить.

Токен GitHub перевыпускается так: https://github.com/settings/personal-access-tokens →
`render-backend-readonly` → Regenerate → новое значение в Render → Environment.
Права нужны минимальные: **только чтение** репозитория `msu-schedule-mobile`.

**Мониторинг:** UptimeRobot пингует `/health` каждые 5 минут, алерт на почту.
Он же не даёт бесплатному Render заснуть (иначе первый запрос за 15 мин простоя ждёт до 50 сек).

## Стиль кода и конвенции

- Комментарии в коде и весь текст интерфейса — **на русском**.
- **Backend:** роутеры в `api/routes/`, логика в `services/`, модели в `models.py`.
- **Web:** каждая страница `"use client"` и сама подключает `<Header/>`. Цвета **только**
  через CSS-переменные (`var(--primary)`, `var(--foreground)`, `var(--muted)`, `var(--card)`,
  `var(--border)`). Тёмная тема — класс `dark` на `<html>`. Захардкоженные цвета ломают тему.
- **Mobile:** цвета через `useTheme()` (объект `C`), иконки `@expo/vector-icons` (Ionicons).
- Тексты дней, пар и групп должны совпадать на всех платформах.

### Менять синхронно в нескольких местах

`shortGroupName`, `PAIR_TIMES`, `PAIR_NUMBERS`, `DAYS_ORDER` продублированы в **backend**,
**web (`lib/api.ts`)** и **mobile (`src/api.ts`)**. Формат хранения пропусков и заметок —
в `lib/studyData.ts` (web) и `src/studyData.ts` (mobile). Меняешь в одном месте — меняй во всех.

Так уже расходилось: в вебе в `shortGroupName` обе половины условия были одинаковыми,
и любая группа со словом «физика» стала бы «ХФММ».

## Функции, открывающиеся 1 сентября 2026

`FEATURES_UNLOCK_AT` в `lib/features.ts` (web) и `src/features.ts` (mobile). Дата читается
как **местное время устройства**, замок снимается сам — ни редеплоя, ни новой версии APK не нужно.

**Но** после разблокировки функции по умолчанию **выключены** — каждый пользователь должен
включить их сам в «Моём кабинете». Это задумано, не баг.

Флаг блокировки нельзя выносить в константу уровня модуля: она вычисляется один раз при
запуске, и приложение, висящее в памяти с августа, показывало бы «закрыто» и 1 сентября.
Проверять только внутри компонента.

**Пропуски.** Отмечается только то, что пропустил; отсутствие отметки у прошедшей пары = «был».
Кнопка есть только у пар, которые уже прошли, и не показывается на экзаменах и зачётах.
Статистика — «пропущено N пар» с разбивкой по предметам.

**Заметки.** По умолчанию закрепляются за слотом «день + пара» и повторяются каждую неделю;
галочкой можно сделать разовой, привязанной к дате.

Данные хранятся **только на устройстве** (localStorage / AsyncStorage), на сервер не уходят.
Переустановил приложение или зашёл с другого телефона — данных нет. Серверные таблицы
`lesson_notes` и `attendance_records` и эндпоинты `/api/user/notes`, `/api/user/attendance`
существуют, но **фронты их не вызывают**.

## Частые задачи

- **Исправить ФИО преподавателя** → панель `/dev` → «Замены ФИО». Без редеплоя.
- **Данные не совпадают с msu.tj** → чинить в `services/parser.py` или `sync.py`,
  сверять с `https://msu.tj/file/timetable/{enf,gf}.xls`.
- **Добавить эндпоинт** → `api/routes/schedule.py` + клиент в `lib/api.ts` (web) и `src/api.ts` (mobile).
- **Проверить логику без реальных данных** (июль-август расписаний нет) → писать временный
  скрипт и гонять на боевом коде с синтетическими данными. Так проверялись перемены,
  окна, «на сегодня всё» и полная неделя на 600 пар.

## Известные слабые места (не срочно, но знать)

- «Изменения» показывают все факультеты вперемешку, без фильтра по своей группе.
- Мобильный `SyncContext` пингует `/api/schedule/groups` каждые 15 секунд ради проверки
  «есть ли сеть» — расточительно, лучше `@react-native-community/netinfo`.
- Полная офлайн-синхронизация мобилки делает сотни запросов подряд; напрашивается
  один bulk-эндпоинт.
- `NEXT_PUBLIC_ADMIN_SECRET` объявлена в Vercel, но в коде не используется. Если её
  когда-нибудь начнут читать — секрет попадёт в браузерный бандл. Лучше удалить.
- Бренд-цвет расходится: дизайн-система `#0e9b72`, а в манифесте, сплэше и иконках `#0d9488`.
